# نيفورا

## التشغيل المحلي

1. ثبّت الاعتماديات باستخدام `npm ci`.
2. انسخ `.env.example` إلى `.env.local`، واضبط `MONGODB_URI` لقاعدة تطوير مستقلة. ولتوليد مفتاح جلسات جديد شغّل:
   ```sh
   node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
   ```
3. عيّن القيمة الناتجة في `JWT_SECRET`، ثم شغّل `npm start` وافتح `http://localhost:3000`.
4. شغّل `npm test` لاختبارات HTTP المعزولة. تشغّل الاختبارات معالجات الخادم وتحاكي قاعدة البيانات، وتستخدم ملفات مؤقتة لفحص المرفقات.

إذا كانت شبكة Windows تعتمد شهادة من مخزن شهادات النظام للاتصال بقاعدة البيانات، شغّل الخادم باستخدام `node --use-system-ca server/server.js`.

## إعداد بيئة النشر

- عيّن سر توقيع جديدًا وبيانات اتصال مستقلة لكل بيئة. غيّر بيانات MongoDB والبريد التي ظهرت سابقًا في تاريخ Git لدى مزوديها.
- عيّن `APP_ORIGIN` إلى عنوان واجهة الويب و`BASE_URL` إلى عنوان الخادم، واضبط `ALLOWED_ORIGINS` عند استخدام واجهات أو تطبيقات إضافية.
- يخزن Render الملفات في MongoDB افتراضيًا عند غياب `PRIVATE_UPLOAD_DIR`. يمكن استخدام `UPLOAD_STORAGE=mongo` على منصات أخرى، أو تخصيص مجلد دائم على الخادم في `PRIVATE_UPLOAD_DIR`. تُخدَم المرفقات وملفات المشاريع عبر مسارات تتحقق من الصلاحية. يحتاج بث الإشعارات اللحظية بين عدة نسخ من الخادم إلى محول Socket.IO مشترك.
- ضبط SMTP وGoogle اختياري للتطوير. عند تفعيلهما في النشر، استخدم عنوان عودة Google المطابق تمامًا لإعداد التطبيق.
- يستخدم الحذف النهائي للمشروع واستيراد النسخة الشخصية معاملات MongoDB. تتوفر هذه العمليات عند تشغيل MongoDB كمجموعة نسخ متماثلة. يتضمن التصدير البيانات الشخصية المدعومة من المشاريع والمهام والقوالب ومسارات العمل.
- يمكن تشغيل `npm run seed` لإضافة تعريفات الخطط أو تحديثها دون حذف الخطط أولًا.
